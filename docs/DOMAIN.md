# Domain Glossary

> **WIP — not set in stone.** These terms are provisional and expected to change as the
> domain is fleshed out. Do not treat any name here as locked.

Generic, system-agnostic vocabulary for the app.

| Term | Meaning |
|---|---|
| **Ruleset** | A body of rules the app references, loaded at runtime. |
| **Army list / Roster** | A user's curated selection of units built toward a goal, validated against constraints. |
| **Unit** | A buildable entry in a roster; carries a points cost and optional equipment/loadout. |
| **Model** | A physical miniature the user owns or plans to own; the atom of the collection. |
| **Loadout / Equipment** | Configurable options attached to a unit that may alter its points cost. |
| **Points budget** | The cap a roster is validated against. |
| **Collection** | The set of models a user owns, each with a build/paint status. |
| **Build/paint status** | Lifecycle of a model: e.g. unbuilt → built → primed → painted → based. |
| **Constraint** | A rule a roster must satisfy to be legal (budget, counts, composition). |

Ruleset content is external input loaded at runtime — the app is the engine, the data is
the user's.
